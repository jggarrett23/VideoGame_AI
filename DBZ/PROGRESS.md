# Project Goal

Build reinforcement learning agents capable of playing popular video games, starting with Dragon Ball Z: Budokai Tenkaichi 3 via the PCSX2 emulator.

- **CLI / launch chain updated** — `train_agent.py` argparse: `--num-envs`, `--patience` added; `run_train_agent.ps1`: `$NumEnvs` param added, passed to both `launch_game.py` and `train_agent.py`; `utils.launch_pcsx2` refactored to support `num_instances` (spawns until N windows exist, returns list of handles); `mcp_pcsx2_server.launch_game` gains `num_envs` param; `launch_game.py` gains `--num-envs` and waits for all N instances to report readable health before exiting (2026-06-20)
- **`WorldModelDQN` model added** — new class in `models.py` jointly trained on three losses: (1) reconstruction — 4-layer strided CNN encodes 4-frame stack to 512-dim latent `z`, transposed CNN decoder reconstructs the most recent frame (MSE); (2) transition — MLP predicts `z_{t+1}` from `concat(z_t, one_hot_action)` vs target-encoder output (MSE); (3) TD — Q-head on `z` trained with standard DQN Bellman update. Loss weights configurable via `TrainConfig` fields `td_loss_weight`, `recon_loss_weight`, `transition_loss_weight` (all default 1.0). Branch: `world_model_dqn` (2026-06-27)
- **Per-component loss logging** — `optimize_model` now returns `Optional[dict[str, float]]` instead of `Optional[float]`; WorldModelDQN path returns `td`, `recon`, `transition`, `total` keys; training loop accumulates and averages each per episode; TensorBoard logs `loss/td`, `loss/reconstruction`, `loss/transition`; episode print line includes breakdown for WorldModelDQN (2026-06-27)
- **`WorldModelDQN` replaced by `ForecastDQN`** — `WorldModelDQN` removed from `models.py`; replaced with `ForecastDQN`, a redesigned architecture addressing two key weaknesses: (1) WorldModelDQN predicted the current window's last frame from earlier frames (T-1→T), giving the transition head a trivial in-window target; ForecastDQN stores T+1 frames in the replay buffer and predicts outside the input window (T→T+1), forcing genuine next-state prediction. (2) WorldModelDQN ran N_actions GRU passes per batch (one per action for the transition loss), making it expensive; ForecastDQN runs a single GRU pass and conditions the forecast head on the taken action's one-hot. Architecture: per-frame `ConvEncoder` (4-layer strided CNN → 256-dim latent) + `ConvDecoder` for reconstruction; GRU dynamics over the frame sequence; `Z.detach()` before GRU isolates encoder from TD/transition gradients; target network (`target_net.frame_encoder`) provides stable forecast targets; L2 normalization of both forecast and target latents bounds transition MSE to [0, 2]. Pairwise cosine similarities between loss gradients (`cos(td,recon)`, `cos(td,trans)`, `cos(recon,trans)`) logged to TensorBoard. Registered in `MODEL_REGISTRY` as `forecast_dqn`; branch `world_model_dqn` reused (2026-06-28)
- **`ForecastDQN` architectural improvements** — three changes applied after diagnosing plateau patterns in the 1909 training run (transition/recon co-plateau at ep ~5, TD loss growing too slowly): (1) `self.forecast` head replaced with a 2-layer MLP (`hidden_dim+n_actions → hidden_dim → enc_dim` with ReLU), giving the head capacity for action-conditional non-linearities; (2) `nn.LayerNorm(hidden_dim)` added on GRU hidden state `Z_h` to prevent state collapse (all states converging to same representation); (3) `transition_loss_weight` lowered from 1.0 → 0.1 in `TrainConfig`, rebalancing GRU gradient signal from ~48:1 (trans:td) to ~5:1 so TD loss can grow. Result: win rate jumped from 8% (2/26 eps) to 39% (11/28 eps) in the 2007 run; reward trend improved from flat ~−0.04 to a steady climb toward −0.003 (2026-06-28)

# Known Issues

- Frame stacking may only save the last frame rather than all 4 — see `Custom_DBZ_Game.py`
- "Fight Again" episode-reset detection is partially implemented; relies on both OCR and health thresholds
- Opponent attack memory address reads are unreliable (noted in `Custom_DBZ_Game.py`); `block_reward` disabled as a result
- Distance threshold (`player_dist_threshold = 1131883873`) is an int/float mismatch — `attack_dist_reward` disabled until verified
